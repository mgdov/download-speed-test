# Download Speed Test — Node.js

Консольный скрипт: 10 последовательных запросов к HTTP(S)-адресу, среднее время запроса, общий объём и скорость скачивания. Только встроенные средства Node.js, без зависимостей.

## Запуск

Требуется **Node.js 22+**. Установка пакетов не нужна.

```bash
git clone https://github.com/mgdov/download-speed-test.git
cd download-speed-test
node download.js "https://example.com/large-image.jpg"
```

Замените пример на URL настоящего файла. Он будет скачан 10 раз — учитывайте трафик и ограничения сервера.

```bash
node download.js "https://example.com/large-image.jpg" --timeout 15
node download.js --help
npm test
```

`--timeout` — максимальное время одного полного запроса, включая чтение тела, в секундах. По умолчанию 30. Таймер отменяет запрос через AbortController; таймер очищается в finally. Это не общий дедлайн всех десяти запросов.

## Алгоритм и единицы

1. В цикле выполняются ровно 10 запросов. Каждый следующий начинается после полного чтения предыдущего ответа.
2. Тело читается потоково; складываются `chunk.byteLength`. Файл целиком в память не загружается и на диск не записывается.
3. `performance.now()` измеряет время каждого запроса от начала fetch до завершения чтения тела.
4. Среднее время: сумма времени / 10. Скорость: общий объём / суммарное время.

**MB/s** — мегабайты в секунду: байты / секунды / 1 000 000. **Mbit/s** — мегабиты в секунду: байты × 8 / секунды / 1 000 000. 1 MB = 1 000 000 байт; 1 Mbit = 1 000 000 бит. Время выводится в секундах.

Пример с условными значениями:

```text
Completed requests: 10
Total downloaded: 10000000 bytes (10.000 MB)
Total request time: 2.000000 s
Average request time: 0.200000 s
Download speed: 5.000 MB/s
Download speed: 40.000 Mbit/s
```

## Ограничения и ошибки

- Измеряется скорость получения данных от конкретного сервера, а не гарантированная пропускная способность интернет-канала. Время включает соединение, ожидание сервера, редиректы и получение тела; fetch может переиспользовать соединения.
- Запрашиваются несжатые данные (`Accept-Encoding: identity`). Если сервер всё же присылает сжатый ответ, fetch автоматически декодирует его: объём отражает байты тела, доступные приложению, а не размер сжатого сетевого трафика. Заголовки и транспортные накладные расходы не учитываются.
- `Cache-Control: no-cache` просит проверить актуальность ответа, но не гарантирует отсутствие кеша на стороне сервера/CDN.
- При HTTP-ошибке, сетевом сбое, обрыве ответа или таймауте тест останавливается с кодом 1 и номером неудачного запроса. Успешный итог по неполным данным не печатается. Некорректные аргументы дают код 2; успех — 0.
- Повторных попыток и параллельных запросов нет. Редиректы обрабатывает fetch; это могут быть дополнительные HTTP-переходы внутри одного из десяти замеров.

## Тесты

```bash
node --test
```

Тесты используют локальный HTTP-сервер без интернета. Проверяют 10 полных последовательных ответов, точный объём, HTTP-ошибку, таймаут при чтении тела, обрыв, chunked-ответ без Content-Length, формулы и аргументы CLI.

## Использование ИИ

Codex использовался для подготовки кода, документации и автоматических проверок. Проверки выполнены на локальном HTTP-сервере. Перед сдачей автору необходимо разобрать код и понимать формулы, асинхронный цикл и отмену запроса.
